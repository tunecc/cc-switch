# provider-context-menu Specification

## Purpose
为供应商卡片提供统一的右键上下文菜单，将原独立的「一键置顶 / 一键置底」小菜单与卡片「更多」菜单的全部操作合并为同一个菜单，使右键成为完整的供应商操作入口。

## Requirements

### Requirement: 供应商右键完整菜单
系统 SHALL 在用户右键点击任意供应商卡片时，在鼠标位置弹出包含以下内容的菜单：

- 「一键置顶」与「一键置底」两项排序操作；
- 原「更多」菜单的全部项：模式相关菜单项（含子菜单行为）、复制、连通性测试、用量配置，以及带禁用原因展示的删除项。

用户 MUST NOT 需要先点击「更多」按钮才能使用上述任一操作。

#### Scenario: 右键菜单包含全部操作（验收：A3）
- **WHEN** 用户右键点击任意供应商卡片
- **THEN** 弹出的菜单同时包含一键置顶、一键置底，以及原「更多」菜单的全部项

### Requirement: 右键菜单排序行为与原实现一致
右键菜单中的置顶/置底 SHALL 与原小菜单行为一致：按新顺序重写全部 sortIndex、刷新供应商列表（及路由类应用的故障转移队列）、更新托盘菜单、成功提示「排序已更新」；目标已在顶部/底部时提示「该供应商已在顶部/底部」且不做修改。

#### Scenario: 置顶行为（验收：A4）
- **WHEN** 用户在右键菜单中对非首位供应商点击一键置顶
- **THEN** 该供应商移动到列表顶部，sortIndex 重写，托盘菜单同步更新，出现成功提示

#### Scenario: 已在顶部
- **WHEN** 用户对已是首位的供应商点击一键置顶
- **THEN** 提示「该供应商已在顶部」，顺序不变

### Requirement: 右键菜单项状态与「更多」菜单一致
右键菜单各项的禁用态、禁用原因展示、连通性测试的测试中禁用、模式项子菜单展开行为 SHALL 与「更多」菜单一致；点击任一项后菜单关闭且动作正常执行。卡片「更多」按钮菜单 MUST 保持原有行为不变。

#### Scenario: 删除禁用原因一致（验收：A5）
- **WHEN** 某供应商删除被禁止（有禁用原因）且用户打开右键菜单
- **THEN** 删除项禁用并展示与「更多」菜单相同的禁用原因

#### Scenario: 「更多」按钮不受影响（验收：A6）
- **WHEN** 用户通过卡片「更多」按钮打开菜单
- **THEN** 菜单项、顺序与行为与本需求变更前一致

#### Scenario: 右键点击菜单项执行动作
- **WHEN** 用户在右键菜单中点击连通性测试
- **THEN** 菜单关闭并打开该供应商的连通性测试弹窗
