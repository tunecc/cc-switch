# 目标

优化供应商逐模型连通性测试弹窗（ConnectivityTestDialog）的三处交互：

1. 模型选择区支持「获取模型列表」：复用模型快捷切换的 `fetch_models_for_config` 上游拉取链路，立即获取远端模型列表，与现有静态清单追加合并去重后多选勾选、加入测试。
2. 默认测试提示词由 `ping` 改为 `你好，你可以帮我做什么事情`（前端默认值与后端兜底同步）。
3. 模仿 ai-toolbox 模型测试的结果区交互：弹窗合并为「配置 + 单一模型表格」形态，打开即展示全部模型行，勾选模型 ID 后点「开始测试」，结果在行内更新，可再次勾选再测，形成「勾选 → 测试 → 结果 → 再勾选」闭环。

# 范围

- `src/components/providers/ConnectivityTestDialog.tsx`（弹窗重构：移除上方选择区、单一模型表格、勾选列、统计卡、获取模型列表按钮）
- `src/hooks/useConnectivityTest.ts`（勾选集合驱动、逐模型流式更新）
- `src/lib/api/connectivity-test.ts`（命令参数）
- `src-tauri/src/commands/connectivity_test.rs`、`src-tauri/src/services/connectivity_test/`（命令按勾选集合过滤、prompt 兜底值）
- `src/lib/connectivityTestSettings.ts`（默认提示词常量）
- 复用（不改其本身）：`src/lib/api/model-fetch.ts`、`ModelQuickSwitchDialog` 的凭据提取逻辑
- 相关 i18n 文案（`src/i18n/locales/*.json`）
- 相关测试（`tests/components/ConnectivityTestDialog.test.tsx`、`tests/lib/`、Rust `commands/connectivity_test.rs` 内嵌测试）

# 非目标

- 不改批量探针链路（供应商列表「批量检测」header 按钮与卡片徽标）
- 不引入 ai-toolbox 的「移除选中/删除失败模型」功能
- 不扩大连通性测试支持的 app 范围（仍为 claude / codex 可测供应商）
- 不改 `ConnectivityDetailDialog` 请求详情子弹窗
- 不改默认测试模型的持久化语义与「保存参数」行为
- 不改模型快捷切换弹窗本身

# 验收示例

- A1 默认提示词：未保存过自定义提示词的供应商打开弹窗，测试提示词输入框显示 `你好，你可以帮我做什么事情`；不传 prompt 时后端实际发送的请求体 prompt 同为该值；保存过自定义提示词的供应商仍恢复其自定义值；`mergeConnectivityTestSettings` 的差异字段判断随新默认值同步（新默认值不被持久化）。
- A2 单一表格形态：打开弹窗即展示该供应商静态清单全部模型行，每行含勾选框、模型 ID、状态、首字节 (ms)、总耗时 (ms)、错误信息、请求详情；初始状态为「待测试」；初始勾选遵循现有预选逻辑（defaultTestModelId → 供应商当前模型 → 清单首个）；表头带全选（含半选态）；上方独立选择区移除。
- A3 获取模型列表：表格区提供「获取模型列表」操作，点击后以供应商 settingsConfig 提取的凭据（与模型快捷切换同源逻辑）调用现有 `fetch_models_for_config` 拉取上游 `/v1/models`；拉取中显示加载态；成功后远端模型按 ID 追加合并去重进表格（新行为待测试、未勾选），仅本次弹窗会话有效、不写回 settingsConfig；失败时显示与模型快捷切换同语义的错误提示（鉴权失败 / 端点不存在 / 超时 / 格式不支持 / 通用失败），静态清单行与测试不受影响；静态清单为空时仍可通过该操作拉到模型开始测试。
- A4 勾选即测试范围：勾选若干模型行点「开始测试」，后端仅对勾选集合发起真实请求，未勾选模型不发送请求（修正现状「后端测全部、前端仅过滤显示」的行为）；测试中勾选行置「测试中」、勾选与开始按钮禁用；每个模型返回后立即更新该行终态（成功/失败 + 首字节/总耗时/错误信息 + 请求详情），无需等待全部模型完成。
- A5 测完勾选行为：一轮测试结束且存在失败模型时，勾选集合自动替换为失败模型（便于直接点「开始测试」重测）；全部成功时保持用户原勾选。
- A6 统计卡：表格上方显示 5 格统计（已勾选 / 运行中 / 成功 / 失败 / 待测试），数值随勾选与行状态实时变化。
- A7 回归不变：默认测试模型下拉、流式开关、高级参数（温度/maxTokens/超时/自定义 Headers/Body）、「保存参数」、请求详情子弹窗、计费免责声明行为与现状一致；批量探针链路不受影响。
- A8 测试：前端单测覆盖默认提示词值、追加合并去重、勾选再测闭环与失败自动勾选；既有 `ConnectivityTestDialog.test.tsx` 等测试随交互重构更新并通过；类型检查与前端构建通过；Rust 侧改动伴随 `cargo test` 通过。

# 约束与不变量

- 测试请求仍走现有 `ConnectivityTestService` 协议实现与请求脱敏逻辑；请求详情、错误结构不变。
- `connectivityTest` 设置块仍仅存与默认值的差异字段（`mergeConnectivityTestSettings` 语义保留；默认提示词变更后判断基准同步更新）。
- 打开弹窗时的参数恢复与默认测试模型预选逻辑（defaultTestModelId → 当前模型 → 首个）不破坏。
- 勾选集合决定后端实际测试范围，不对未勾选模型发送真实请求。
- 远端拉取的模型仅在弹窗会话内生效，不持久化、不触碰供应商 settingsConfig。
- UI 沿用现有 shadcn 组件体系与 i18n 文案键（`connectivityTest` 命名空间）。

# 决策

- D1（结果区形态）：合并为单一表格——打开弹窗即展示全部模型行（初始待测试），勾选行 → 开始测试 → 行内更新；移除上方独立选择区。理由：与 ai-toolbox 形态一致，选择与结果一体化，勾选再测闭环最自然。
- D2（远端合并）：追加合并去重——远端拉取的模型按 ID 追加进静态清单并集。理由：静态清单是已配置模型、远端是可用全集，并集给用户最完整选择面。
- D3（测完勾选）：自动勾选失败项——测试结束若有失败模型，勾选集合替换为失败项；全部成功时保持原勾选。理由：模仿 ai-toolbox 且便于一键重测失败项。
- D4（统计卡）：加上 5 格统计卡（已勾选 / 运行中 / 成功 / 失败 / 待测试）。理由：模仿 ai-toolbox 的整体结果概览。
- D5（状态更新粒度，实现选择）：逐模型独立请求并行、逐行流式更新（模仿 ai-toolbox 的每模型一请求模式），替代现有「一次 invoke 整批、统一写终态」。
